# Round 10 on the PC layer: what it tests, its config, and what it changes from round 9

Set 2026-11-13 for the developer's approval (smoke first). Launcher: `scripts/pc/pc_round10.sh`. Fixes and their evidence:
[round 9 fixes](2026-11-10-round9-fixes.md), [failures](../failures.md); channel: [token channel design](2026-11-12-mip-token-channel-design.md).

## What it is

A development run, not a measurement: `r10-rows` includes rows the fixes were built from, so a gain says the mechanisms work as built
and the model uses them, nothing about a fresh set. The measurement after it is frozen10 (PC layer and A100).

## What it tests

1. **A vs B: do round 9's fixes help, against round 9 as it ran.** Arm A is round 9's General exactly (the developer, 2026-11-13: "ให้เทียบกับรอบ9ได้"),
   so A also reads against round 9's own records on the 56 rows round 9 ran (112 answers, 86 right).
2. **B vs CH: the same mechanisms put as text against steered through the token channel** (nothing inserted under the channel).
3. **Every touch's value, right or wrong**, checked again independently: gate 3 (`scripts/pc/gate3_values.py`) for CH, per mechanism,
   split by answers that finished right and wrong; then whether it was needed; last what it did to the answer (A vs B, B vs CH pairs).

**What counts** (from the round 9 fixes plan): B right more often than A, one-sided sign test p < 0.05 on the rule score and the API
reader's corrected score both; no value put by B's or CH's mechanisms wrong; no right -> wrong pair caused by a touch left unread (a pair
that parts before the first touch is path noise). **"What counts" is read twice: on every pair, and on the pairs where `--question-line`
did not fire** (a question that is one fixed computation gets software's value at the start; the model then closes its thinking at once,
as in the smoke's `div_big` row), so the sign test cannot pass on software-computed values alone. **A against round 9's own records is
totals, not pairs** (another server build, `-np` and pool): it is the noise floor on the 56 shared rows. An all-on arm measures each mechanism at its touches only; which mechanism moved an
answer needs an ablation arm, not in this run.

## The arms

**A = round 9's General** (no change):
`--inline-calc --mathbackend --inline-plain --inline-style general` software's value after `=`, plain;
`--no-digit-join` no digit glued onto a put; `--guard-progress` nothing put on a looping line; `--loop-close` `</think>` on a thinking
loop; `--answer-close` a looping answer cut and the final answer asked; `--early-cycle` an exact cycle caught early;
`--shape-cap 1024 --cover-cap 32768` the loop-shape detectors' bounds.

**B = A + the changes from round 9, put as text:**

| Flag | What it changes | Round 9 failure it addresses ([failures](../failures.md)) |
|---|---|---|
| `--think-only` | values only in the thinking, none in the final answer | the General Style rule of 2026-11-12 |
| `--question-quote` | the question's own expression put back when the model's copy reads to another value, and at a thinking loop's close | P4 precedence misread (`(-25)/X*1/(-4)`); P5 `simplify_surd` loops counting parentheses |
| `--approx-put` | after `\approx`/`≈`, the value to 10 significant digits | P11 `(1.01)^{30} \approx 1.3448888` |
| `--long-value` | at `=`, an exact value too long to be a step, cut to 10 significant digits with `...` (refused before) | P11 at `=` (`1.01^{30} = 1.3448888...`, miss1 B) |
| `--answer-rewind 2` | an answer loop cut out whole and resampled, up to twice, before the forced cue | P12 the close boxed an unfinished step |
| `--letter-count` | the letters of a string the question writes out, counted, at the start | P7 `swr_p_sequence` letters miscounted or miscopied |
| `--question-line` | a question that is one fixed computation gets `expr = value` at the start of the thinking | a fixed computation is software's (developer, 2026-11-12) |

**CH = B + `--channel`:** the same values steered through the token channel: the model writes them; nothing is inserted (letter count and
question line as the start plan, the quote handed to the next request, the loop close injected as before). Parity on round 9's
traces: letter count 10 / 10, copy quote 4 / 4, loop-close quote 41 / 41 the text arm's exact text (`results/token-channel/channel-parity.txt`).

**Not in this run:** the Sandbox arm (`--execute --box --loop-hint --verify-gate`, the 2026-11-11 plan's C): it runs model code on the
developer's PC, a separate decision. Round 9's misses no mechanism reaches stay wrong (rounded or integer-part boxes, `cot⁻¹` range
convention, a figure only in the solution).

# รอบ 10 บน PC layer: ทดสอบอะไร config อะไร แก้อะไรจากรอบ 9

**เป็น development run ไม่ใช่การวัดผล** เพราะ `r10-rows` มีข้อที่ใช้สร้างการแก้อยู่ด้วย ถ้าได้ผลดีขึ้นก็บอกได้แค่ว่ากลไกทำงานตามที่สร้างและโมเดลใช้มันจริง การวัดจริงคือ frozen10

**ทดสอบอะไร**
1. A เทียบ B: การแก้ของรอบ 9 ช่วยหรือไม่ เทียบกับรอบ 9 ตามที่รันจริง (A คือ General ของรอบ 9 ทุก flag จึงเทียบกับผลรอบ 9 ได้ใน 56 ข้อที่รอบ 9 เคยรัน)
2. B เทียบ CH: กลไกชุดเดียวกัน ใส่เป็นข้อความ กับ steer ผ่าน token channel โดยไม่แทรกอะไร
3. ทุกจุดที่กลไกแตะ ค่าที่ใส่ถูกหรือผิด ตรวจซ้ำแบบอิสระ (gate 3) แยกตามคำตอบที่จบถูกและผิด

**เกณฑ์:** B ถูกมากกว่า A ด้วย sign test p < 0.05 ทั้งคะแนนตามกฎและคะแนนที่แก้ด้วย API reader, ค่าที่ใส่ต้องไม่ผิดเลย, ถ้าคู่ไหนถูกกลายเป็นผิดเพราะกลไกแตะ ต้องอ่านจนเข้าใจทุกคู่ ส่วนจะรู้ว่ากลไกตัวไหนทำให้คำตอบเปลี่ยนต้องมี arm ที่ปิดทีละกลไก ซึ่งไม่อยู่ในรอบนี้

**Config:** 4B NVFP4 W4A8 · llama.cpp+MIP · PC layer บน RTX 5060 Ti ใบเดียว (ไม่แตะ 4070 SUPER) ใช้ `-c 524288 -kvu -np 16` และ KV q8_0, T 0.6, seed 1-2, full context, CUDAMathBackend ทุก arm, 73 ข้อ × 2 seed × 3 arm = 438 คำตอบ ประมาณ 11-13 ชั่วโมง

**สิ่งที่แก้จากรอบ 9 (arm B และ CH)**
- `--think-only` ใส่ค่าเฉพาะในส่วนคิด
- `--question-quote` ยกนิพจน์ของโจทย์มาให้เมื่อโมเดลคัดลอกผิด และตอนปิด loop (P4, P5)
- `--approx-put` ใส่ค่า 10 หลักหลัง `\approx` (P11)
- `--long-value` ใส่ค่าที่ยาวเกินจะเขียนเป็นขั้นที่ `=` โดยตัดที่ 10 หลักพร้อม `...` (P11 ที่ `=`)
- `--answer-rewind 2` ตัดคำตอบที่วนออกทั้งก้อนแล้วให้เขียนใหม่ ไม่เกิน 2 ครั้ง ก่อนจะบังคับคำตอบ (P12)
- `--letter-count` นับตัวอักษรของ string ในโจทย์ใส่ไว้ตอนเริ่ม (P7)
- `--question-line` โจทย์ที่เป็นการคำนวณตายตัว ได้บรรทัด `expr = value` ตอนต้นส่วนคิด

CH ใช้กลไกเหมือน B ทุกตัว แต่ steer ผ่าน channel ให้โมเดลเขียนค่าเอง ไม่มีอะไรถูกแทรก ส่วน arm Sandbox ไม่อยู่ในรอบนี้ เพราะต้องรันโค้ดของโมเดลบนเครื่องคุณ

## Smoke

1. `r10smoke2-rows` (`div_big-928`, `swr_p_sequence-5920`), 1 seed, 3 arms: 6 / 6 right (rule and API reader); the channel 117 asks,
   34 plans, 34 steered, 0 dropped, 0 missed asks; gate 3 34 / 34 right and written as steered; 15.3 of 16.3 GB on the 5060 Ti. Fired:
   the inline value, `--question-line` (B and CH). Not fired: the letter count (that row gives letters as `{o: 1, ...}`, no string),
   the quote, `--approx-put`, `--long-value`, `--answer-rewind`. A second smoke covers them before the full run.

2. `r10smoke3-rows` (`swr_p_sequence-3480`, `simplify_surd-3480`, `stdmath-45fa3ef2`, round 9's P7, P5, P11 rows), 1 seed, 3 arms:
   right A 1 / 3, B 3 / 3, CH 3 / 3 (rule and API reader agree; one seed, not a result). Every mechanism fired: the letter count
   (B, CH), the question quote (B at the loop close; CH handed and steered), `--approx-put` (B 34, CH 16), `--long-value` (B 7, CH 3;
   none in A, the flag is off), `--answer-rewind` (CH 2), the loop and answer closes. The channel 373 asks, 130 plans, 130 steered,
   0 dropped, 0 missed asks; gate 3 130 / 130 right and written as steered. The text arm's approx and long values were read by hand:
   right (`1.10462212541120451001^3 = 1.347848915...` is `1.01^{30}`). Gate 3 and the reader were run by hand after the launcher,
   edited while it ran, failed to parse its own tail: a running `sh` script is not edited.

**Known risk:** a KV pool overflow returns an HTTP error that ends the arm's process (miss1's first try); `RESUME=1` restarts the arms
from their records.
